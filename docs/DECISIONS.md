# Decisions

Decisions taken during the autonomous build where the specification was ambiguous or the environment forced a choice. Architectural decisions also have an ADR in `docs/adr/`.

| Date | Decision | Alternatives | Reason |
|---|---|---|---|
| 2026-10-16 | `.claude/settings.json` is kept at `docs/harness/settings.json` until the maintainer copies it into place. | Work around the denial; drop the file. | The Claude Code auto-mode classifier denies writes to the agent's own settings as self-modification. The content is complete and tested; only its location differs. Listed under "Needs the maintainer". |
| 2026-10-16 | Go module requires `go 1.25.0` with `toolchain go1.27.2`. | `go 1.27.0` as the language version. | 1.27.2 is the latest stable toolchain at build time; the language floor is the one required by `modelcontextprotocol/go-sdk` v1.8.0 so that linters built with older toolchains still parse the code. |
| 2026-10-16 | A policy bundle that fails to compile at startup denies every call and fails `/readyz` (FR-4); a failed hot reload keeps the last good bundle serving, `/readyz` stays 200 but reports `policy: stale: last reload failed: ...`, and the failure is logged (a metric and alert are planned in T-38). | Deny everything and fail readiness on any failed reload. | §4.1 requires that "a failed reload keeps the previous bundle and alerts"; failing readiness would remove every replica from service because of a typo in a not-yet-active bundle. FR-4's deny-all applies when no bundle has compiled. See ADR 0002. |
| 2026-10-16 | Idempotency records are bound to the tool as well as the args hash (`sha256(server.tool + NUL + args_sha256)`); `args_sha256` in the audit log stays the hash of the arguments only. | Bind only to args (contract text). | M2 review: the same key and args on another tool would otherwise replay the other tool's result. |
| 2026-10-16 | `arguments: null` or absent in tools/call is evaluated as `{}`; non-object arguments are rejected with -32602. | Pass null through. | M2 review: `args = null` is the tools/list signal, so argument rules (approval for credit notes, refund limits) would not fire. |
| 2026-10-16 | Approvals are also bound to the held call's idempotency key. A retry of an already-consumed approval with the same key and arguments continues to the idempotency stage (replay, or re-execution under the same key after a failed attempt, still deduplicated upstream); any other reuse is `-32045 approval_consumed`. | Treat every second use as `approval_consumed`. | A timeout after consumption would otherwise strand an approved operation; the idempotency layers already guarantee a single write. |
| 2026-10-16 | Write calls without a valid idempotency key are rejected (`-32041`) before the policy stage. | Validate the key in the idempotency stage. | A held call must carry the key its approved retry will use; failing early avoids approvals that can never be consumed. |
| 2026-10-16 | Audit `seq` is allocated when a call reserves its audit slot (Postgres sequence `audit_events_seq`, prefetched in blocks of 1,024 by `audit.PostgresSeq`); the hash chain is ordered by a separate gap-free `chain_pos` assigned by the writer under `pg_advisory_xact_lock`. `audit verify` walks `chain_pos` and names the first bad `seq`. | Assign `seq` at flush time (then `_meta.mcpgw.audit_seq` could not be returned); a per-process counter (not replica-safe). | The contract needs `audit_seq` in every result, while replicas must extend one chain (§4.6). Deleting a row is detected as a `chain_pos` gap. |
| 2026-10-16 | Every call reserves an audit slot (buffer 10,000) and its seq before any side effect; without one within 1 ms the call fails `-32048` and nothing executes. The event is committed after the outcome is known, so each outcome writes exactly one event. | Enqueue only at the end (a write could run and then fail to audit). | Fail closed (NFR-3) without auditing gaps. Calls rejected by audit backpressure itself produce no event (recorded in KNOWN_LIMITATIONS). |
| 2026-10-16 | Audit hash input: canonical JSON (RFC 8785, `pkg/canonicaljson`) of the event without `hash`, timestamps truncated to microseconds in UTC (`2006-01-02T15:04:05.000000Z`), `latency_ms` rounded to microseconds, `args_redacted` canonicalised. | Hash the stored JSON as-is. | Events must hash identically after a Postgres round trip (timestamptz and jsonb normalise values). |
| 2026-10-16 | Canonical JSON rejects non-I-JSON input: invalid UTF-8, unpaired surrogate escapes, duplicate keys and integers beyond ±2^53 (`-32602` for tool arguments). | Accept and normalise. | Two different inputs must never hash the same (M1 review). |
| 2026-10-16 | Upstream-side dedup (`pkg/mcpserver`) runs the write and records the key in one transaction detached from the caller's context (`context.WithoutCancel`, 60 s cap); the stored result is returned from jsonb on replay. | Cancel the write when the caller disconnects. | Models a real system that finishes work after its caller timed out; the same-key retry then replays (chaos scenario). |
| 2026-10-16 | Refunds lock the order row in one statement and sum existing refunds in a second statement. | One `SELECT ... FOR UPDATE` with a subquery. | Under READ COMMITTED the subquery used the pre-lock snapshot, letting concurrent refunds exceed the order (M1 review, `TestInsertRefundSerialisesOnOrderLock`). |
| 2026-10-16 | Principals with `tenant: "*"` (dev personas platform engineer and security reviewer) see every tenant in the admin API; approvers must have a concrete tenant and can only decide that tenant's approvals; other tenants' approvals and audit events look missing on reads (404), while deciding another tenant's approval returns 403 (`ErrForbidden`); the contract allows either. | Separate cross-tenant scope. | Least privilege for approvers (§15) while letting reviewers audit everything. |
| 2026-10-16 | Sessions of the legacy MCP session protocol are bound to the principal (tenant, agent, scope set) through the SDK's token-info user id; the gateway serves one `*mcp.Server` per principal and resyncs it in place on catalog or policy changes. | Stateless-only handler. | Prevents session reuse across principals (`TestSessionBoundToPrincipal`) and lets agents receive `tools/list_changed`. |
| 2026-10-16 | Policy listing input sends `args: null`; `tools/call` always sends an object. Listing shows a tool when the decision is allow or require_approval. | Separate listing policy. | Spec §4.4; argument rules must not fire for listing. |
| 2026-10-16 | Rate limits: tenant and per-agent token buckets plus a daily budget in one Redis Lua script with micro-token integer arithmetic and the gateway's clock; unknown tenants get a conservative default (1/s, burst 5, 100/day). When Redis fails, reads use a per-process bucket and writes fail `-32049`. | Redis `TIME`; floating-point tokens. | Exact, testable refills (fake clock) and fail-closed writes (§4.6). |
| 2026-10-16 | Injection scoring: `imperative_density` counts imperative verbs only at clause starts (after punctuation, newline, "and", "then", "please"), URLs excluded; phrase matching also runs on de-spaced and leetspeak-folded text; NINO pattern accepts any two letters (HMRC's own example is `QQ 12 34 56 C`). | Count every verb token. | Nouns like "email" mid-sentence produced false positives on benign notes; evals tune on dev only. |
| 2026-10-16 | Card redaction checks the whole digit run, then group-aligned sub-windows (13-19 digits); an unseparated run longer than 19 digits is not treated as a card. | Regex plus Luhn on the whole match only. | A card followed by an expiry or CVV was missed (M2 review); long reference numbers stay readable. |
| 2026-10-16 | JWKS: known keys are served from cache until the stale limit while a single-flight refresh runs in the background; unknown kids trigger at most one synchronous fetch per 10 s, with backoff after failures. | Fetch synchronously under a mutex. | A hung issuer must not serialise verification (M2 review). |
| 2026-10-16 | Approval webhooks are delivered from a Postgres outbox written in the same transaction as the approval; retries back off 2 s doubling to 1 h; after 24 attempts the row is abandoned (`next_attempt_at = infinity`, kept for the runbook). Webhook `tool` is the namespaced name. | Fire-and-forget POST. | Spec §4.6; no lost notifications when the sink is down. |
| 2026-10-16 | Admin API: audit pagination cursor is the decimal `chain_pos` of the last event; every `/admin` query parameter must appear once with a non-empty value; filter values containing NUL return an empty page; invalid UTF-8 is 400. | Opaque base64 cursor; ignore empty parameters. | Found by Schemathesis (int4 overflow, schema-valid inputs rejected); the spec is strict and documented in `api/openapi.yaml`. |
| 2026-10-16 | Container healthcheck probes `/readyz` (policy, Postgres, Redis) rather than `/healthz`, and the image sets absolute paths (`MCPGW_POLICY_DIR=/policies`, `/config/*.yaml`). | Liveness probe as healthcheck. | `docker compose up --wait` must mean ready; a missing policy dir was otherwise invisible (fail-closed deny-all). |
| 2026-10-16 | Compose publishes every port on 127.0.0.1 only; the example upstreams share role `mcpgw_upstream`; role passwords are set by `mcp-gateway migrate` from `MCPGW_*_DB_PASSWORD` (never in migrations); goose takes a Postgres advisory lock. | 0.0.0.0 ports; passwords in migrations. | Local-only dev stack (M0 review); secrets from the environment only. |
| 2026-10-16 | Tools not downloadable in Claude Code on the web (GitHub releases blocked): hadolint and promtool run from their official images through wrappers in `./bin`, trivy is built with `go install`, Helm with `go install helm.sh/helm/v3/cmd/helm`. All Go tools are built with the module toolchain (`GOTOOLCHAIN` from `go.mod`). | Skip those checks. | Appendix A fallbacks; golangci-lint must be built with Go >= the module's toolchain. |
| 2026-10-16 | Example tool definitions are registered without a database (`upstreams.New(name, nil)`), so catalog and discovery tests use the real schemas and annotations. | Hand-written fake tools. | Tests compare the gateway's listing against the upstreams' own definitions (FR-1). |
| 2026-10-16 | Audit args are made storable before hashing: integers beyond ±2^53, NULs (in values, keys and string fields) and non-JSON are replaced by `[REDACTED:NUMBER]`, `[REDACTED:NUL]` and `"[REDACTED:INVALID_JSON]"`. Sinks mark data errors (canonicalisation, SQLSTATE classes 22 and 23) as `ErrUnstorable`; the writer then halves the batch until the offender is alone and stores a placeholder (same seq and status, args `"[REDACTED:UNSTORABLE]"`); only if that is refused too is the event dropped, with an error log. | Retry the batch until it succeeds (previous behaviour); reject the call before audit. | M3 review: one hostile call stalled the writer forever, filled the buffer and turned every later call into -32048. |
| 2026-10-16 | Audit events are served with `ts` in the hashed layout (`2006-01-02T15:04:05.000000Z`), so any consumer re-hashes an event from the API JSON. | Document the layout and let clients reformat. | M3 review: `time.Time`'s default JSON drops trailing zeros, which broke re-hashing for about 10% of events. |
| 2026-10-16 | A consumed approval answers any reuse with `approval_consumed` (checked before the binding), except the same-binding retry, which continues to the idempotency stage and replays. | Report `approval_mismatch` for a different binding. | Matches the documented reasons; a spent approval is spent whatever the caller sends. |
| 2026-10-16 | At most one pending approval per call (unique partial index `approvals_one_pending`, migration 00005); `Create` expires a stale pending row first and returns `ErrDuplicatePending` on conflict, and `Hold` returns the existing approval. Outbox rows are claimed with `FOR UPDATE SKIP LOCKED` for a 15 min lease. | Advisory locks; a per-replica outbox. | M3 review: concurrent identical holds created two approvals and two webhooks; replicas could deliver one webhook twice. |
| 2026-10-16 | `/admin/audit/verify` and the console's verify button need a cross-tenant viewer or `mcpgw:admin`; a webhook URL needs a secret of at least 16 bytes. | Allow any audit reader; accept an empty secret. | Verification reveals chain-wide facts and forces a flush; an empty HMAC key makes signatures forgeable. |
| 2026-10-16 | Audit list queries are built from the filters in use (no `($n = '' OR col = $n)`), and `approval_id` is compared as a uuid after a shape check. | One static query. | Lets the planner use the tenant and approval indexes (NFR-8: `BenchmarkAuditPage` p95 11.31 ms over 100,000 rows). |
